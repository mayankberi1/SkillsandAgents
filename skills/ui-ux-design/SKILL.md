# ui-ux-design

## Activation and inputs

Specify user journeys and accessible screen interactions. Relevant roles: UI Designer, Product Owner, Tester, Developer. Inputs: Approved requirements and existing UI conventions. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Apply the shared collaborative discovery policy. Ask about users, tasks, accessibility, devices and preferences; discuss representative journeys and state transitions. Brainstorm interaction options or useful wireframes with the user and confirm behaviour rather than inventing material experience choices.

Map journeys to screens and navigation. Specify normal/loading/empty/error states, input validation and recovery. Include accessibility and responsive requirements. Use wireframes when they resolve uncertainty; no mandatory prototype. Define observable acceptance behaviour and request applicable UI approval.

## Outputs and boundaries

UI proposal, state specifications and criteria. Include decisions, deliverable references, evidence, risks/blockers and next action. Testing-verification validates behaviour; no implementation.
