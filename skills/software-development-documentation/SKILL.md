# software-development-documentation

## Activation and inputs

Reconcile concise product/design/iteration docs with actual work. Inputs: Actual implementation, approved decisions and stage reports. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Maintain only applicable roadmap/backlog/design/iteration records. Reference requirement IDs rather than separate exhaustive matrices. Align Mermaid components, classes, sequences and data/trust flows with actual code; include meaningful error paths. Record significant ADRs only when warranted. Reconcile discrepancies and approval revisions; propose backlog updates without changing existing entries unauthorised.

Reconcile `docs/product-backlog.md` with linked requirements, designs, iterations, approvals and verification using the shared product backlog contract in software-development-workflow. The main chat maintains the backlog when the environment permits. Preserve IDs and history; report conflicts before dependent work.

## Outputs and boundaries

Consistent documentation, diagrams and discrepancies. Include decisions, deliverable references, evidence, risks/blockers and next action. Does not manufacture verification evidence or approval provenance.
Before you write any direct response to me, ensure it is written in ASD-STE100 Simplified Technical English, do not use techno-babble of any kind, do not physicalize things, always use the simplest turn of phrase, no need for synonymous phrases for variety, and use active voice.
Be concise and minimalist.
Use more diagrams, charts, and bullet points list, and tables to convey more in less words.
