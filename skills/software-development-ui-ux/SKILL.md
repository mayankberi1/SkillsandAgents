# software-development-ui-ux

## Activation and inputs

Specify user journeys and accessible screen interactions. Inputs: Approved requirements and existing UI conventions. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Follow the collaborative discovery rules in software-development-workflow. Ask about users, tasks, accessibility, devices and preferences; discuss representative journeys and state transitions. Brainstorm interaction options or useful wireframes with the user and confirm behaviour rather than inventing material experience choices.

Map journeys to screens and navigation. Specify normal/loading/empty/error states, input validation and recovery. Include accessibility and responsive requirements. Use wireframes when they resolve uncertainty; no mandatory prototype. Define observable acceptance behaviour and request applicable UI approval.

## Outputs and boundaries

UI proposal, state specifications and criteria. Include decisions, deliverable references, evidence, risks/blockers and next action. Testing-verification validates behaviour; no implementation.
Before you write any direct response to me, ensure it is written in ASD-STE100 Simplified Technical English, do not use techno-babble of any kind, do not physicalize things, always use the simplest turn of phrase, no need for synonymous phrases for variety, and use active voice.
Be concise and minimalist.
Use more diagrams, charts, and bullet points list, and tables to convey more in less words.
