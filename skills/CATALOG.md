# Skill catalogue

Load relevant skills on demand through native discovery; request exact-name loading explicitly when needed. See central AGENTS.md for shared governance. These skills are canonical portable definitions, not globally installed.

| Skill | Purpose / activation | Capabilities / output | Relevant agents | Overlap / dependencies |
|---|---|---|---|---|
| [agent-planning](agent-planning/SKILL.md) | Track every agent assignment and reconcile scope coverage. | Per-agent Markdown task plan, evidence/status checkpoints and remaining work | All agents | Coordinator persists specialist-owned plans; complements iteration-planning without granting approvals or edit permissions. |
| [requirements-analysis](requirements-analysis/SKILL.md) | Clarify requirements, scope and acceptance criteria before design. | Requirements proposal; criteria; open questions; approval target | Product Owner, Coordinator | Feeds iteration-planning and design; does not select architecture. |
| [iteration-planning](iteration-planning/SKILL.md) | Plan small iterations from approved requirements and designs. | Reviewable iteration records and scoped approval proposal | Coordinator, Product Owner, Developer, Tester | Uses approved design outputs; implementation is separate. |
| [architecture](architecture/SKILL.md) | Evaluate boundaries, dependency direction and architectural alternatives. | Architecture proposal, alternatives and constraints | Architect, Solution Designer, Code Reviewer | Dependency-assessment supplies library trade-offs; solution-design details contracts. |
| [solution-design](solution-design/SKILL.md) | Design implementable component, API and data contracts. | Detailed design proposal and implementation contracts | Solution Designer, Architect, Developer | Architecture defines boundaries; documentation-diagrams maintains views. |
| [ui-ux-design](ui-ux-design/SKILL.md) | Specify user journeys and accessible screen interactions. | UI proposal, state specifications and criteria | UI Designer, Product Owner, Tester, Developer | Testing-verification validates behaviour; no implementation. |
| [incremental-implementation](incremental-implementation/SKILL.md) | Implement an approved iteration with small scoped tested changes. | Scoped diff, tests, evidence and handoff | Developer | debugging-recovery handles failed checks; code-simplification evaluates reduction. |
| [testing-verification](testing-verification/SKILL.md) | Independently verify acceptance, integration and failure behaviour. | Passed/Failed/Not run/Blocked/Not verified evidence and gaps | Tester, Developer, Code Reviewer, Security Reviewer | Does not replace code/security review; tests may write artifacts and need tool authorisation. |
| [debugging-recovery](debugging-recovery/SKILL.md) | Diagnose defects and reconcile interrupted workflows safely. | Diagnosis/remediation evidence or recovery proposal | Developer, Tester, Coordinator | Implementation owns fixes; recovery never invents missing approval. |
| [code-review](code-review/SKILL.md) | Independently review actual changes against requirements and design. | Review verdict, findings, reviewed scope and limitations | Code Reviewer, Architect | Mandatory code-simplification assessment complements review; security-privacy is independent. |
| [code-simplification](code-simplification/SKILL.md) | Assess unnecessary complexity without weakening required behaviour. | Simplification assessment, justified exceptions and scoped proposals | Developer, Code Reviewer, Solution Designer | Does not authorise cleanup or remove required safeguards. |
| [security-privacy](security-privacy/SKILL.md) | Assess every changed file and relevant trust/privacy risks. | Per-file assessment, findings, evidence, limits and blocking/exception decisions | Security Reviewer, Architect, Tester, Developer | dependency-assessment informs dependency risk; prompt instructions are not deterministic security. |
| [dependency-assessment](dependency-assessment/SKILL.md) | Compare dependency and internal implementation options before changes. | Evidence-backed dependency recommendation and approval target | Architect, Developer, Code Reviewer, Security Reviewer | Architecture chooses material design; release-readiness assesses compatibility/version impacts. |
| [documentation-diagrams](documentation-diagrams/SKILL.md) | Reconcile concise product/design/iteration docs with actual work. | Consistent documentation, diagrams and discrepancies | Coordinator, Product Owner, Architect, Solution Designer, UI Designer, Developer | Does not manufacture verification evidence or approval provenance. |
| [release-readiness](release-readiness/SKILL.md) | Assess release readiness, versions and changelog without source-control operations. | Release-readiness report and version/changelog proposal | Coordinator, Developer, Code Reviewer | User manages source control/publication; debugging-recovery reconciles file/record state. |
