# iteration-planning

## Activation and inputs

Plan small iterations from approved requirements and designs. Relevant roles: Coordinator, Product Owner, Developer, Tester. Inputs: Approved requirements/designs and actual file state. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Inspect the approved file baseline and changed-file inventory. Partition work into independently verifiable increments. For each record goal, requirement IDs, files, dependencies, plan, acceptance/tests, reviews, docs and approvals. State stage, risks and next action. Identify explicit batch boundaries and invalidate affected approvals when revised.

Link feature iterations to backlog item ID and scope revision. Follow the shared product backlog contract in agent-planning and return stage/progress/evidence and proposed status to Coordinator at checkpoints. Iteration completion alone does not mean feature Done.

## Outputs and boundaries

Reviewable iteration records and scoped approval proposal. Include decisions, deliverable references, evidence, risks/blockers and next action. Uses approved design outputs; implementation is separate.
