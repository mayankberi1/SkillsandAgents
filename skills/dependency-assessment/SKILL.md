# dependency-assessment

## Activation and inputs

Compare dependency and internal implementation options before changes. Relevant roles: Architect, Developer, Code Reviewer, Security Reviewer. Inputs: Required capability, existing versions and authorised research. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Compare reuse, standard library, third-party and internal solutions fairly. Assess functionality, licence, security, maintenance, compatibility, complexity and total ownership cost using evidence. Preserve current versions absent approval. Document transitive/contract impacts and significant alternatives. Propose any installation/upgrade for approval; never install as part of assessment.

## Outputs and boundaries

Evidence-backed dependency recommendation and approval target. Include decisions, deliverable references, evidence, risks/blockers and next action. Architecture chooses material design; release-readiness assesses compatibility/version impacts.
