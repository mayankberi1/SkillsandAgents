# software-development-planning

## Activation and inputs

Plan small iterations from approved requirements and designs. Inputs: Approved requirements/designs and actual file state. Read applicable central AGENTS.md; this capability grants no additional authorisation.

## Procedure

Before planning, ask about unresolved delivery choices and offer options with a recommendation. Inspect the approved file baseline and changed-file inventory. Partition work into independently verifiable increments. For each, record goal, requirement IDs, files, dependencies, coding approach, plan, acceptance/tests, reviews, docs and approvals. State stage, risks and next action. Identify explicit batch boundaries and invalidate affected approvals when revised.

Link feature iterations to backlog item ID and scope revision. Follow the shared product backlog contract in software-development-workflow. Present the complete coding plan, affected files, steps, checks and risks for approval before coding starts. Show stage, progress, evidence and proposed status at checkpoints. Wait for approval before the next stage. Iteration completion alone does not mean feature Done.

## Outputs and boundaries

Reviewable iteration records and scoped approval proposal. Include decisions, deliverable references, evidence, risks/blockers and next action. Uses approved design outputs; implementation is separate.
